# 单步自回归预测方案说明

> 文件：`train_transformer_autoregressive.py`
> 对应原版：`train_transformer.py`（直接多步输出，**保持原样未改动**）
> 适用模型：`TimeSeriesTransformer` / `iTransformer`（均复用原模型结构，不改模型源码）

---

## 1. 背景与目标

原 `train_transformer.py` 采用**直接多步输出（direct multi-step）**：

- 模型 head = `Linear(d_model, horizon * output_dim)`，一次 forward 直接输出整个预测窗口（24 步）。
- 无自回归、无 teacher forcing，训练可并行，推理一次出全部 horizon。

本方案将其改为**单步自回归（single-step autoregressive / free-running rollout）**：

- 模型 head 只输出 **1 步**（`horizon=1`），每次只预测下一个点。
- 把**上一轮的预测结果当作输入**窗口的最新一行，再喂给模型预测下一个点，循环往复，滚动出整个预测窗口。

> 即原版是“一次出 24 步”，新版是“分 24 次、每次出 1 步，前一次的预测喂回去当输入”。

---

## 2. 与原版的核心区别

| 维度 | 原版 `train_transformer.py` | 新版 `train_transformer_autoregressive.py` |
|---|---|---|
| 输出方式 | 直接多步，head 一次出 horizon 步 | 单步 head，自回归 rollout 滚动 horizon 步 |
| 模型 horizon | `horizon=predict_steps`（24） | `horizon=1` |
| 训练前向 | `model(x, target_len=24)` 一次出 24 步 | `autoregressive_rollout(...)` 循环 24 次单步 forward |
| 每步输入来源 | 仅回看窗口 | 上一轮预测回灌 + 未来外生真值补齐 |
| 每 batch forward 次数 | 1 次 | 24 次（按 horizon 串行） |
| batch_size | 32 | 16（串行 forward 显存/时间更重，调小控显存） |
| 推理脚本 | 原直接多步推理 | 需配套 `autoregressive_rollout`，**不能用原推理脚本** |

数据清洗、特征工程、归一化、序列生成口径、评估指标（MAE/RMSE/MAPE、按预测起点时刻统计）、画图全部与原版一致，**仅替换“前向输出方式”**。

---

## 3. 自回归 rollout 设计

### 3.1 数据序列：额外返回“未来外生特征行”

原 `DataProcessor.make_sequences` 返回 `(X, Y)`（回看窗口 / 未来目标）。新增 `make_sequences_ar`，额外返回 `Xf`（未来 horizon 步的**完整特征行**），供 rollout 时补齐外生通道：

```
X  : (N, lookback_steps, C)   回看窗口
Y  : (N, horizon,        1)   未来目标 (Total_Flow)
Xf : (N, horizon,        C)   未来 horizon 步完整特征行 (含目标通道)
```

> `Xf` 中的目标通道在 rollout 中会被本轮预测值覆盖；其余外生通道用真值（外生 teacher forcing）。

### 3.2 rollout 逻辑

`autoregressive_rollout(model, src, future_exog, predict_steps, target_feat_idx, detach_feedback)`：

```
输入:
  src             : (B, L, C)  ground-truth 回看窗口 (feature 域)
  future_exog     : (B, H, C)  未来 H 步外生特征行 (目标通道将被覆盖)
  target_feat_idx : 目标通道 (Total_Flow) 在 C 维的下标
  detach_feedback : 回灌预测是否 detach

循环 (predict_steps 次):
  1. one = model(window, target_len=1)          # (B,1,1) 单步预测下一个点
  2. feedback = one[:,0,0]                      # 本轮预测 (按 detach 开关决定是否 detach)
  3. next_row = future_exog[:, k:k+1].clone()   # 取第 k 步未来外生特征行
  4. next_row[:, 0, target_feat_idx] = feedback  # 目标通道替换成本轮预测 → 回灌
  5. window = cat([window[:, 1:], next_row])     # 丢最旧一行, 末尾拼 next_row → 滑窗前进
收集每步预测 → (B, H, 1)
```

### 3.3 为什么外生通道用真值、只回灌目标通道

模型 `output_dim=1`，**只预测目标 Total_Flow**。但输入窗口是多维特征（流量 + 压力 + 泵状态/频率 + 时间/滞后/滚动统计）。要滑窗前进，下一个时刻必须有一整行 C 维特征：

- **目标通道**：由模型自己上一轮的预测回灌 ← 这就是“把上一轮预测当输入”的部分。
- **外生通道**：模型无法生成（压力、泵状态、泵频率、时间特征、滞后/滚动特征），只能用 ground-truth 未来行补齐（外生 teacher forcing）。

这与原直接多步模型口径一致——原版也不预测外生通道，只是原版根本不把未来步喂进输入。单目标预测下，外生通道无法由模型自生成，必须用真值补齐。

> 说明：`Xf` 里的时间/滞后/滚动特征是 data_processing 阶段基于 ground-truth 流量预计算的，并非由预测值重算。这是预计算特征管线的固有性质（原版同样如此），本方案不改变特征工程，只改输出方式。

### 3.4 域一致性

- 回看窗口 `src` 处于 feature_scaler 域；其中目标通道 Total_Flow 与 target_scaler 域同（`target_transform=None` 时两 scaler 标定同一原始列，均值/方差相同）。
- 模型预测输出处于 target_scaler 域 = 目标 feature 通道域，回灌到目标通道时域一致，无需额外转换。
- iTransformer 的 RevIN 对窗口做实例归一化/反归一化，滑窗变化时每步重算统计量，对回灌预测天然兼容。

## 4. `detach_feedback` 开关

回灌到下一步输入的预测值是否 detach，决定梯度如何传播：

| 值 | 行为 | 适用 |
|---|---|---|
| `True`（默认） | 回灌预测值 detach，梯度只训练当前步。模型仍能看到“自己上一轮的预测”作为上下文（缓解 exposure bias），但避免 24 步 BPTT 的显存爆炸 / 数值不稳定 | 稳定、省显存，推荐默认 |
| `False` | 完整 BPTT，梯度穿过整条 rollout 链，模型端到端学习“我之前的预测如何影响后续预测”。显存按 horizon 倍增，可能 OOM | `--no-detach-feedback`，需大显存 |

命令行：
```bash
python train_transformer_autoregressive.py                     # 默认 detach=True
python train_transformer_autoregressive.py --no-detach-feedback # 完整 BPTT
python train_transformer_autoregressive.py --model transformer # vanilla Transformer
```

> 默认 `detach_feedback=True`：模型每步用“含自己先前预测的上下文”训练当前步，是介于 teacher forcing 与纯 free-running 之间的折中——既让模型暴露于自身预测误差，又稳定可训。

## 5. 训练 / 评估流程

训练循环（每 batch）：
```
for batch_x, batch_y, batch_xf in train_loader:
    pred = autoregressive_rollout(model, batch_x, batch_xf, predict_steps,
                                  target_feat_idx, detach_feedback)  # (B,H,1)
    loss = weighted_mse_loss(pred, batch_y)
    loss.backward(); clip_grad_norm_(1.0); optimizer.step()
```

评估 `evaluate(...)` 同样调用 `autoregressive_rollout`（`torch.no_grad()`，detach 不影响）。

指标口径与原版完全一致：
- `weighted_mse_loss`：仅目标通道 MSE。
- 反归一化后算 MAE / RMSE / MAPE（MAPE 按全局阈值过滤近零流量点）。
- 画 best/worst 样本图、误差分布图、按步 MAE、按预测起点时刻统计、loss 曲线。

## 6. 持久化与推理注意

`scaler.pkl` 在原版基础上额外保存：
```
{
  "config", "feature_scaler", "target_scaler", "feature_cols", "target_cols",
  "autoregressive": True,
  "target_feat_idx": <int>,
  "detach_feedback": <bool>,
}
```

> ⚠ **重要**：本模型是单步头（`horizon=1`），**不能用原直接多步推理脚本加载**。推理必须使用配套的 `autoregressive_rollout`（与训练同一份实现），并喂入对应的未来外生特征行。后续如需推理脚本，需单独编写自回归版 inference。

---

## 8. 小结

- 原版“一次出 24 步” → 新版“单步 head + 滚动 24 次，前次预测回灌为输入”。
- 回灌只覆盖目标通道，外生通道用真值补齐（单目标预测的固有约束）。
- `detach_feedback` 在“稳定省显存”与“完整 BPTT”间切换，默认稳定档。
- 数据 / 特征 / 评估口径与原版完全一致，仅改前向输出方式，便于公平对比两种范式的预测精度（尤其长 horizon 误差累积特性）。
